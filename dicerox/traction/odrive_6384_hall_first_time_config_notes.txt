ODrive v3.6 Clone + 6384 120KV Hall Motor
First-Time Bring-Up Config, Calibration Sequence, and Tuning Notes

Context
-------
This note is for a first-time bring-up of a 6384 120KV motor with Hall sensors on an ODrive v3.6-style board.
Assumptions:
- Motor: 6384, 120 KV
- Poles: 14 poles -> 7 pole pairs
- Feedback: Hall sensors (A/B/Z used as Hall A/B/C)
- Battery: 6S pack
- Brake resistor: physical 2 ohm resistor present
- Axis used: axis0

Important practical note
------------------------
On this specific board/motor combination, repeated motor calibration attempts may be flaky.
If the first calibration succeeds, save the result and avoid recalibrating repeatedly unless wiring or hardware changed.

Useful equations
----------------
1) Pole pairs:
   pole_pairs = poles / 2
   pole_pairs = 14 / 2 = 7

2) Hall CPR:
   CPR = 6 * pole_pairs
   CPR = 6 * 7 = 42

3) Torque constant approximation:
   kT ~= 8.27 / KV
   kT ~= 8.27 / 120 = 0.0689 N*m/A

4) Approximate motor torque:
   T ~= kT * Iq
   Example at 30 A:
   T ~= 0.0689 * 30 = 2.07 N*m
   This is ideal motor torque before losses and before gearing.

5) Brake resistor power:
   P = V^2 / R
   At 22.2 V and 2 ohm:
   P ~= 22.2^2 / 2 = 246.4 W
   At 25.2 V and 2 ohm:
   P ~= 25.2^2 / 2 = 317.5 W

   This shows that a 2 ohm / 50 W resistor may only tolerate strong braking for short intervals.
   It is not a large continuous dump solution.

====================================================================
1) BASE CONFIG BEFORE CALIBRATION
====================================================================

Paste this first in odrivetool:

import odrive, time

dev0 = odrive.find_any()

# ---------- POWER ----------
dev0.config.dc_bus_undervoltage_trip_level = 19.5
dev0.config.dc_bus_overvoltage_trip_level  = 26.0

dev0.config.enable_brake_resistor = True
dev0.config.brake_resistance = 2.0

# battery-friendly shared-pack regen
dev0.config.dc_max_negative_current = -2.0
dev0.config.max_regen_current = 1.0

# optional bus draw ceiling
dev0.config.dc_max_positive_current = 20


# ---------- HALL GPIO ----------
dev0.config.gpio9_mode  = GPIO_MODE_DIGITAL
dev0.config.gpio10_mode = GPIO_MODE_DIGITAL
dev0.config.gpio11_mode = GPIO_MODE_DIGITAL


# ---------- MOTOR ----------
dev0.axis0.motor.config.motor_type = MOTOR_TYPE_HIGH_CURRENT
dev0.axis0.motor.config.pole_pairs = 7
dev0.axis0.motor.config.torque_constant = 8.27 / 120.0

# first-time calibration settings
dev0.axis0.motor.config.calibration_current = 5

# runtime torque settings
dev0.axis0.motor.config.current_lim = 30
dev0.axis0.motor.config.requested_current_range = 35
dev0.axis0.motor.config.current_lim_margin = 5


# ---------- ENCODER ----------
dev0.axis0.encoder.config.mode = ENCODER_MODE_HALL
dev0.axis0.encoder.config.cpr = 42
dev0.axis0.encoder.config.bandwidth = 100


# ---------- CONTROLLER ----------
dev0.axis0.controller.config.control_mode = CONTROL_MODE_VELOCITY_CONTROL
dev0.axis0.controller.config.input_mode   = INPUT_MODE_VEL_RAMP

dev0.axis0.controller.config.vel_limit = 30
dev0.axis0.controller.config.vel_ramp_rate = 1.0

dev0.axis0.controller.config.pos_gain = 1
dev0.axis0.controller.config.vel_gain = 0.07
dev0.axis0.controller.config.vel_integrator_gain = 0.008

dev0.axis0.config.startup_closed_loop_control = False


# ---------- CLEAR PRE-CAL FLAGS ----------
dev0.axis0.motor.config.pre_calibrated = False
dev0.axis0.encoder.config.pre_calibrated = False


Now save and reboot:

    dev0.save_configuration()
    dev0.reboot()

Reconnect:

    dev0 = odrive.find_any()
    dev0.clear_errors()

Expected note:
- save_configuration() or reboot() will disconnect the USB device briefly.
- On this board that is expected.

====================================================================
2) ONE-TIME CALIBRATION SEQUENCE
====================================================================

2A) Motor calibration
---------------------

    dev0.axis0.requested_state = AXIS_STATE_MOTOR_CALIBRATION

    while dev0.axis0.current_state != AXIS_STATE_IDLE:
        time.sleep(0.1)

    dump_errors(dev0)

If there are no motor errors:

    dev0.axis0.motor.config.pre_calibrated = True

If motor calibration fails on a true first-time motor:
- Check phase wiring
- Check motor connector quality
- Check supply voltage/current
- Check Hall power and Hall ground
- Do not spam calibration forever without checking hardware

2B) Hall polarity calibration
-----------------------------

    dev0.clear_errors()
    dev0.axis0.requested_state = AXIS_STATE_ENCODER_HALL_POLARITY_CALIBRATION

    while dev0.axis0.current_state != AXIS_STATE_IDLE:
        time.sleep(0.1)

    dump_errors(dev0)

2C) Encoder offset calibration
------------------------------

    dev0.clear_errors()
    dev0.axis0.requested_state = AXIS_STATE_ENCODER_OFFSET_CALIBRATION

    while dev0.axis0.current_state != AXIS_STATE_IDLE:
        time.sleep(0.1)

    dump_errors(dev0)

If there are no encoder errors:

    dev0.axis0.encoder.config.pre_calibrated = True

2D) Save calibrated state
-------------------------

    dev0.save_configuration()
    dev0.reboot()

Reconnect:

    dev0 = odrive.find_any()
    dev0.clear_errors()

At this point the calibration should be stored.

====================================================================
3) NORMAL RUNTIME USE
====================================================================

Every normal startup after calibration:

    dev0 = odrive.find_any()
    dev0.clear_errors()
    dev0.axis0.requested_state = AXIS_STATE_CLOSED_LOOP_CONTROL

Command velocity gradually:

    dev0.axis0.controller.input_vel = 0
    dev0.axis0.controller.input_vel = 2
    dev0.axis0.controller.input_vel = 4
    dev0.axis0.controller.input_vel = 6
    dev0.axis0.controller.input_vel = 8

Practical initial operating envelope:
- 0 to 8 turn/s as normal
- 10 turn/s as higher-load testing
- 15+ turn/s may exceed the comfortable torque/current envelope on this setup

====================================================================
4) WHAT TO EDIT DEPENDING ON THE GOAL
====================================================================

A) If you want more torque
--------------------------
Main parameter:
- current_lim
Secondary paired parameter:
- requested_current_range

Suggested progression:

    dev0.axis0.motor.config.current_lim = 35
    dev0.axis0.motor.config.requested_current_range = 40

If still needed and thermals are safe:

    dev0.axis0.motor.config.current_lim = 40
    dev0.axis0.motor.config.requested_current_range = 45

Effects:
- Harder to stop the wheel by hand
- More available wheel torque
- More heating in motor and driver
- Greater chance of current-related faults if pushed too far

What to watch:
- Motor temperature
- Driver temperature
- Burning smell
- CURRENT_LIMIT_VIOLATION faults

B) If you want less ramp / softer acceleration
----------------------------------------------
Main parameter:
- vel_ramp_rate

Softer:

    dev0.axis0.controller.config.vel_ramp_rate = 0.7

Even softer:

    dev0.axis0.controller.config.vel_ramp_rate = 0.5

Effects:
- More gentle acceleration and deceleration
- Lower shock to drivetrain
- Less aggressive response when a command changes

If instead you want more aggressive ramp:

    dev0.axis0.controller.config.vel_ramp_rate = 1.5

C) If you want less overshoot after disturbing the wheel by hand
----------------------------------------------------------------
Main parameters:
- vel_gain
- vel_integrator_gain

Safer / more damped version:

    dev0.axis0.controller.config.vel_gain = 0.07
    dev0.axis0.controller.config.vel_integrator_gain = 0.008

If it still rebounds too much:

    dev0.axis0.controller.config.vel_gain = 0.08
    dev0.axis0.controller.config.vel_integrator_gain = 0.005

Interpretation:
- vel_gain adds damping
- vel_integrator_gain helps remove steady-state speed error, but too much can create windup and rebound

D) If you want stronger steady-state speed hold
-----------------------------------------------
Main parameter:
- vel_integrator_gain

More aggressive speed-holding:

    dev0.axis0.controller.config.vel_integrator_gain = 0.01

Even stronger, but riskier:

    dev0.axis0.controller.config.vel_integrator_gain = 0.015

Tradeoff:
- Better recovery to commanded speed under load
- More overshoot risk after release of the load

E) If you want more battery protection from regen
-------------------------------------------------
Main parameters:
- dc_max_negative_current
- max_regen_current

More battery-protective:

    dev0.config.dc_max_negative_current = -1.0
    dev0.config.max_regen_current = 0.5

Interpretation:
- Try to send almost no charge current back into the battery
- Ask the brake resistor to start helping very early

Tradeoff:
- More likely to fault if braking is harsh or the resistor is too small

F) If you want less nuisance regen faults
-----------------------------------------
Less conservative version:

    dev0.config.dc_max_negative_current = -3.0
    dev0.config.max_regen_current = 1.5

Tradeoff:
- Battery sees more regen current
- Less likely to fault under braking

====================================================================
5) HOW TO THINK ABOUT THE CURRENT SETTINGS
====================================================================

current_lim
-----------
- Motor-side current limit for torque production
- Main runtime torque knob
- More current_lim -> more torque potential

requested_current_range
-----------------------
- Legacy measurement/sensing range parameter
- Usually set somewhat above current_lim
- Not the main performance knob

current_lim_margin
------------------
- Extra margin above current_lim before a violation becomes a problem
- Useful when terrain causes sudden load changes

dc_max_negative_current
-----------------------
- Battery/DC-bus side limit on how much current is allowed back into the battery/supply
- Negative because it is current flowing back toward the source

max_regen_current
-----------------
- Threshold where brake resistor action starts helping with regen energy
- If regen becomes larger than desired, the resistor should dissipate the extra energy

Simple interpretation:
- current_lim = how much motor current I allow for torque
- requested_current_range = sensing range around that current
- current_lim_margin = tolerance above the normal current limit
- dc_max_negative_current = how much charging current I allow back into the battery
- max_regen_current = when I ask the brake resistor to start helping

====================================================================
6) QUICK DIAGNOSTICS
====================================================================

After calibration, useful checks:

    print("motor pre-cal:", dev0.axis0.motor.config.pre_calibrated)
    print("encoder pre-cal:", dev0.axis0.encoder.config.pre_calibrated)
    print("hall response:", dev0.axis0.encoder.calib_scan_response)
    dump_errors(dev0)

During runtime, useful live variables:

    print("vel:", dev0.axis0.vel_estimate)
    print("Iq:", dev0.axis0.motor.current_control.Iq_measured)

If supported on your firmware, monitoring bus current and resistor current is also helpful.

10. reboot()
